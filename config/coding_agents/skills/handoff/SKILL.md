# コマンドの受け渡し（handoff）

ユーザーに `! <長いコマンド>` のコピペを依頼しない。ターミナルの折り返しで改行が混入し、そのまま貼るとエラーになるため。代わりにコマンドをステージングファイルに書き、ユーザーには `! h` だけを依頼する。

## 手順

1. ステージングファイルのパスを取得する: Bash で `h --path` を実行する（作業対象リポジトリ内で実行すること。キーは git toplevel なので worktree ごとに別ファイルになる）
2. Write ツールで、そのパスに実行してほしいコマンドを書く
   - Bash の heredoc では書かない。PreToolUse hook が本文中の `git push --force` 等を検出して拒否するため
   - `!` はセッションのカレントディレクトリで実行される。リポジトリ外のパスに依存する場合だけ `cd` を明示する
   - 複数行・複数コマンドを書いてよい。途中で止めたい場合は先頭に `set -e` を置く
3. ユーザーへの依頼文には、実行内容を 1〜2 行で説明し、コマンド本文をコードブロックで示したうえで、実行用に `! h` だけを案内する。コマンド本文は確認用であり、コピーさせない
4. ユーザーが `! h` を実行すると、出力（冒頭にステージされたコマンド全文が表示される）が会話に入る。それを読んで結果を確認し、作業を続ける

## 注意

- `h` は実行前にステージングファイルを `<hash>.last.sh` へ移す。失敗しても再実行で同じコマンドは走らないので、やり直す場合は再度ステージする
- `h` は確認プロンプトを出さない（`!` は非対話で実行されるため）。ユーザーの確認は手順 3 で示すコマンド本文で行う。示した内容とファイルの内容を必ず一致させる
- `h --show` で現在ステージされている内容を確認できる
- 権限ルールの回避目的では使わない。deny は「ユーザー本人の判断で実行する」ための線引きであり、handoff はその判断を楽にする手段に過ぎない
